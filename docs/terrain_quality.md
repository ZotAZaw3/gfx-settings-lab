# Terrain Quality

> Menu: **World → Terrain Quality** · Setting id: `world.terrainQuality` (Low / Medium / High / Ultra) · Owner module: `geometry.terrain`
> Presets: Low…Ultra
> Files: `src/modules/geometry/terrain.cpp`, `shaders/geometry/terrain.*`, heightfield in `geo_util.cpp` (`HeightField::generate`)

## Definition

Terrain quality controls how detailed the ground of an outdoor world is: the
resolution of the height field, how much geometric detail is added near the camera, how
far detailed terrain extends, and how many material layers (grass, rock, sand, snow) are
blended per pixel.

## How it works

1. **Height field.** The ground is a 2D grid of heights (e.g. 4097² samples over 4 km).
2. **Terrain LOD.** Rendering every sample is impossible, so terrains use a
   view-dependent mesh:
   - **Geo-clipmaps**: nested rings of a fixed grid, each ring twice as coarse; the rings
     move with the camera. Constant cost regardless of world size.
   - **Quadtree / CDLOD**: split the terrain into a quadtree; nodes near the camera
     subdivide. CDLOD *morphs* vertices between levels in the VS to avoid cracks/popping.
   - **Hardware tessellation** on coarse patches (see `tessellation.md`). Used here.
3. **Crack fixing.** Neighbouring patches at different LODs must share edge vertices:
   skirts, stitching strips, or (with tessellation) matching edge factors.
4. **Materials.** A splat map stores per-texel weights for 4–16 layers. The pixel shader
   blends layers with **height-based blending** (the taller layer wins at the boundary,
   so stones poke through sand). Triplanar mapping avoids stretching on cliffs.
5. **Runtime virtual texturing (RVT)**: the blended terrain material is baked into a
   virtual texture cache around the camera, so the expensive blend runs once per texel
   instead of once per pixel per frame.

## Breakdown

**In this prototype:**

1. Stage `GBuffer`, order 10 — same pass as tessellation. Terrain Quality picks the patch grid (16² / 24² / 32² / 48²
   over 160 m), caps the tessellation factor (16 / 32 / 64 / 64) and the material layers (2 / 3 / 4 / 4, cliffs
   projected sideways from Medium up).
2. The heightfield (512² R32F) is generated once on the CPU (fBm + ridges, flattened plaza, lake basin) and the
   same data is used by the culling occluder, grass placement and the fog's terrain shadows.


| Level  | Patch grid | Max tess | Height samples/m | Layers blended | Triplanar |
|--------|-----------|----------|------------------|----------------|-----------|
| Low    | 16²       | 8        | 0.5              | 2              | no        |
| Medium | 24²       | 16       | 1                | 3              | cliffs    |

Cost: vertex/tessellation (shape), pixel (material layers × texture fetches,
triplanar = 3× fetches), memory (height + splat maps, streaming).

## Optimization

- Clipmaps or CDLOD give constant vertex cost; tessellation adds adaptive detail.
- Only blend layers whose weight > 0 (branch on splat weights, or sort per tile).
- Triplanar only where slope is steep.
- RVT / baked macro textures for distant terrain.
- Lower terrain detail in shadow passes; often use a separate low-res terrain
  heightmap shadow.

## Rebuild (from scratch)

1. Create a heightmap texture (R16 or R32F), here generated by fBm noise on startup.
2. Build an `N × N` grid of patch corner points spanning the terrain (N from the table).
3. Draw it as `GL_PATCHES` with 4 vertices; TCS picks levels by screen-space edge
   length, capped by `Max tess`; TES samples the heightmap and displaces (see
   `tessellation.md` for full shader code).
4. In the FS, recompute the normal from the heightmap with central differences and
   blend layers using height-based weights:
```glsl
vec3 blendLayers(vec3 c0,float h0,float w0, vec3 c1,float h1,float w1){
    float d = 0.2;
    float m = max(h0 + w0, h1 + w1) - d;
    float b0 = max(h0 + w0 - m, 0.0), b1 = max(h1 + w1 - m, 0.0);
    return (c0*b0 + c1*b1) / (b0 + b1);
}
```
